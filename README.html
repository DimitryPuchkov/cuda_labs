cuda_lab1

Задание

Реализовать программу для накладывания фильтров на изображения. Возможные фильтры: размытие, выделение границ, избавление от шума. Изменить время Для работы с графическими файлами рекомендуется использовать libpng (man libpng). Примеры использования библиотеки в /usr/share/doc/libpng12-dev/examples/ Считать изображение из файла, преобразовать в массив, отправить на CUDA Device, провести на устройстве обработку фильтром, вернуть изображение в память хоста, преобразовать в картинку, сохранить файл.

Характеристики устройства

Имя устройства: NVIDIA GeForce RTX 3090 Ti
Количество мультипроцессоров: 84
Объем глобальной памяти: 25756696576 байт
Максимальное количество потоков на блок: 1024
Максимальный размер сетки: 2147483647 x 65535 x 65535
Максимальный размер блока: 1024 x 1024 x 64

Описание программы

Для считывания и записи изображения использовал библиотеку stb_image, так как ее настройка оказалась наиболее легкой (просто скопировать файлы .h в папку с программой). Реализовал программу только для 3 канальных изображений (RGB). Размер блока выбрал 16х16 (256 потоков) так как такое число не очень большое (доступно на большинстве видеокарт) и делится на 32 - число одновременно обрабатывающихся потоков.

Основная идея:

Обработка изображения представляет собой применение свертки с ядром 3х3, следовательно для обработки каждого пикселя необхолдима информация из текущего пикселя а также соседних пикселей (halo) вокруг текущего (всего информация из 9 пикселей считая текущий) а также ядро светрки. Каждый из потоков обрабатывает свой пиксель (так как сетка содиржит в общем случае больше потоков чем пикселей в изображении, то не все потоки будут выполнять работу). По условию задания необходимо использовать общую память, она доступна всем потокам в блоке, и так как необходима информация о соседних пикселях размер общей памяти вычисляется как размеры блока по x и по y увеличенные на 2: по одному пикселю с каждой стороны и умноженные на число каналов изображения (3). В ядрах происходит вначале заполнение shared memory а затем после барьерной функции (чтобы дождаться когда вся общая память будет заполнена) происходит применение свертки. Также по условию задания производится замер времени: общего, передачи данных на устройство, выполнения ядра, передачи памяти на хост.

Общий план работы программы:

  1. Считывание изображения
  2. Инициализация памяти на устрйстве и передача данных на устройство
  3. Обработка изображения: 3.1 Заполнение общей памяти 3.2 Применение свертки
  4. Передача обработанного изображения на хост
  5. Сохранение изображения

Реализованные фильтры:

  • Blur - равномерный фильтр размытия
  • Sobel - фильтр собеля для выделения границ

Результат выполнения программы

Программу запускал на 2 изображениях: большом (5824х3264) и маленьком (196х257).

Результаты на маленьком изображении

Blur Параметр Время (ms) Передача данных на GPU 4.2528e-02 Обработка 1.9779e-01 Передача данных на хост 6.1664e-02 Общее вермя 1.6367e+02

Вывод

  • Функции sinf и __sinf работают с типом float и в случае передачи double делают каст во float поэтому что на типе float что на типе double ошибка прмерно в 7-9 знаке, а функция sin работает с типом double, а в случае передачи float конвертирует его в double поэтому при рассчетах с помощью этой функции и типа double достигается наименьшая ошибка в 18 знаке.
  • Функция sin оказалась наиболее быстрой (на обоих типах данных наименьшее время), хотя теоретически sin должен быть самым долгим, sinf побыстрее, а __sinf самым быстрым. Полагаю такой результат был получен в связи с применяемыми оптимизациями (запускал в visual studio) такими как кеширование результатов в sin (для sinf и __sinf нет такого по умолчанию). Была гипотеза что это происходит из-за явного приведения типов, однако запуск без явного приведения с float и с double не выдал качественно другого результата. Однако в реальных задачах когда нет возможности кешировать результат лучше всего будет использовать __sinf как самую быструю функцию.
